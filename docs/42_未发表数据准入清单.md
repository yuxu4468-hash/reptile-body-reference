# 42. 未发表数据准入清单（U1 档）

> **适用对象**：任何**能提供成体系种群记录**的人 —— 不限定身份。
> ⚠️ **告示里不要出现任何身份类别**（繁殖者 / 玩家 / 养殖场 / 「有规模的」）——
> 一提就变成在**给身份分类**，反而会把只养十几只的人挡在外面（他觉得自己「不够规模」）。
> 只谈**数据**（有没有一个种群、有没有孵化日期与定期测量），不谈**人**。
> **判据是记录是否成体系，不是身份**（2026-10-08 用户两次指出）。
> **不适用**：单个玩家随手报的一个数字（那仍然不收 —— 见 §1）。
>
> 立这份清单的起因（2026-10-08）：有 7 个物种在本项目**完全无数据**，而它们里有几个
> 恰恰是人工繁殖量极大的热门种（睫角守宫、花龟、钟角蛙…）。这些物种的"暂无可靠数据"
> 虽然诚实，但对用户**没有帮助**。用户提出「单列一组、标明低可靠性」，
> 本文把这个想法**收敛成可执行的规则**。

---

## 1. 为什么"整批种群记录"与"玩家随手自报"不是一回事

| | 随手自报的一两条 | **成体系的整批种群记录** |
|---|---|---|
| 样本量 | n=1 | **n=几十～几千** |
| 孵化日期 | 多半不知道 | ⭐ **知道**（→ 年龄层可做） |
| 饲养条件 | 各异、未记录 | **统一、可描述** |
| 提供者 | 匿名路人 | **具名、可追问** |
| 选择偏倚 | 谁爱报谁报 | **是整批，不是自选** |

**右边那种不是"众包噪声"，是未发表的一手种群数据。** 所以它走的是 `U1` 档，
不是"接受了众包"。

⚠️ 但两者**共有一个缺陷**：**只反映单一饲养条件**。这一条**必须写进卡面**，
不能只写"低可靠性"（见 §4）。

---

## 2. 三道门槛（沿用 §3 的布尔判据，不评分）

| # | 门槛 | `U1` 档的具体要求 |
|---|---|---|
| **G1** | **测量口径明确** | 提供者**事先接受**我们的测量约定（见 `docs/43` 的图示），并在数据里**逐列写明**。**做不到 → 不收。** ⚠️ 不接受"推断口径"那条降级通道（§3.1），因为它要求同批双口径数据，单次提交给不出 |
| **G2** | **可溯源到一手来源** | 来源 = **可回联的联系方式 + 提供日期**。一手来源**不必是已发表文献**，也**不必公开署名** —— 本条要的是「我们找得到人核对」，不是「对方要公开身份」。⚠️ **对外默认匿名** |
| **G3** | **样本量与观测范围已报告** | 逐条数据都在，n 与范围是从数据里算出来的，不是估的。
⚠️ **不设数量下限** —— 本项目自己的曲线里就有 n<30 的（最小 n=3），
对外不要求比我们自己更高的门槛 |

**另外两条 `U1` 专属**：

| # | 要求 |
|---|---|
| **U-a** | **必须是个体级**。只有均值 / 只有区间 → 不收（无法拟合，也无法算散度）。
**不设 n 的下限**：有几条算几条 |
| **U-b** | **同一只动物要能区分**（有编号或稳定标识）。否则重复测量会被误当独立个体 |

## 3. 红线（**由数据结构强制，不靠人记得**）

| # | 红线 | 怎么强制 |
|---|---|---|
| **R1** | **绝不与文献数据混排** | `U1` 记录**不进入 `curves` 数组**，只进 `lowRelCurves`。对照计算与卡片渲染**在物理上就碰不到它们** |
| **R2** | **绝不作为默认参照** | 同上 —— 它不在 `curves` 里，用户必须**主动展开**「未发表数据」区块才看得到 |
| **R3** | **只在「该物种 / 该类型 / 该口径完全无文献数据」时收** | `tools/merge_records.py` **在入库前拒绝**：若同物种同类型同口径已有 L1/L2 记录，`U1` 一律不入库 |
| **R4** | **带宽整体叠加该层的不确定度** | 复用已有的 `caliber_uncertainty_len_pct` 机制 |
| **R5** | **声明事实，不下判断** | 橙色警示框，写**事实**：「未发表」「来自单一饲养群体」「未经同行评审」。
⚠️ **不要写「低可靠性」这类评判词** —— 对外征集的文案里尤其不能有
（默认对方的数据不可靠会劝退提供者，用户 2026-10-08 指出）。
事实照写，判断留给读者 |

> **R3 为什么重要**：它正是「缅甸蟒养殖场年龄曲线被拒收」与新规则**不矛盾**的原因 ——
> 缅甸蟒已有 n=3986 的可靠数据，所以按 R3，那条养殖场曲线**仍然不收**。

---

## 4. 卡面必须写出来的话（不是可选）

1. **来源**：谁提供的、什么时候、什么饲养条件（温度/饲料/密度，能写多少写多少）
2. **未经同行评审**
3. **来自单一饲养群体** —— 换成别人的饲养条件可能差很多
4. **不是文献数据，不能与上面的卡片对比**
5. n、口径、观测范围、是否有带刻度照片凭证
6. **选择偏倚**：这是**该繁殖者的一批个体**，不是随机样本

> 第 6 条与本项目一贯的「**显示数据的薄弱，而不是隐藏它**」完全一致。

---

## 5. 数据形态（按优先级）

| 优先级 | 形态 | 说明 |
|---|---|---|
| ⭐⭐⭐ | **带刻度照片 + 逐条表格** | 每个个体一张（尺子入镜）→ 测量**可核验** |
| ⭐⭐ | **逐条表格 + 部分照片** | 至少幼体段有照片 |
| ⭐ | **纯逐条表格** | 收，但卡面要写明「无影像凭证」 |
| ✗ | 只有均值 / 只有区间 | **不收**（过不了 G3 与 U-a） |

## 6. 入库流程

```
繁殖者提交（docs/43 模板）
   ↓
逐条检查 G1/G2/G3/U-a/U-b          ← 缺一即退回，不"补一个估计值"
   ↓
独立复算：自己重新拟合，不信对方给的 b / r²
   ↓
指数可辨识性：b 的 95%CI 不得跨 1–4    ← 同文献数据一个标准
   ↓
跨度 ≥10%（否则不能拟合幂函数）
   ↓
R3 检查：同物种同类型同口径是否已有文献数据？有 → 不入库
   ↓
标 U1，进 lowRelCurves（与 curves 物理隔离）
   ↓
全量测试（含"低可靠层不得出现在主对照表"的断言）
```

---

## 7. 什么时候**不**该用这一档

- 该物种**已有任何文献数据** → 直接做文献卡，不开 `U1`（R3）
- 提供者**不愿留任何联系方式** → 过不了 G2，不收。
  （但**不愿公开署名**完全没问题 —— 内部可回联即可，对外默认匿名）
- ⚠️ **不要问对方身份**（是繁殖者还是玩家？养了多少年？）—— 与数据质量无关，且会劝退。
  判据是**记录是否成体系**，不是身份
- 只是"想帮忙"但**没有系统记录** → 那不是种群数据，是零散自报，不收
